Data & improvement notes

Storage: db is the in-memory state. loadDB() loads JSON from this browser's localStorage; saveDB() validates and writes changes, then refreshes the view. Data is not sent to a server and does not sync between devices.

Access: demo roles control which buttons are shown, but browser-only roles are not security. A real multi-user CRM needs server-side authentication, authorization, database transactions, backups and audit controls.

Improvement demonstrated: the starter's hard-delete workflow was replaced with archive/restore plus an audit log, so records can be recovered and changes reviewed.
